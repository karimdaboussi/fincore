# Contributing

Describe the problem and expected behavior in an issue or pull request. Keep changes focused and include regression coverage for business rules or failure handling.

Before submitting, run the Java formatting/build checks and frontend formatting, unit, build, and browser checks listed in the README. Use a disposable PostgreSQL database for integration tests. Explain any skipped checks and their requirements in the pull request.

Keep credentials and generated output out of commits. Update setup instructions and the architecture guide when changing module boundaries, configuration, or API behavior. Use synthetic data in screenshots and examples.
